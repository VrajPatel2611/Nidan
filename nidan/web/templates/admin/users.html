The decision this screen has to make first

An administrator cannot currently read a learner's sessions, by policy. sessions has row-level security on and own_sessions carries no TO clause, so it binds nidan_admin like everyone else; migration 034 opened exactly two keyholes, both keyed on a leakage flag — an admin may read a session because it carries a flag, and only the one event the flag points at. Not the learner's questions.

So "show me this user's sessions" is a product and privacy decision before it is a screen, and this is where it should be argued — not widened quietly in a migration to make some other page work.
